# Вехи

Практическое руководство по вехам (milestones) — контрольным точкам по срокам.

## Что такое веха и чем отличается от эпика {#what}

**Веха — это точка на оси времени.** Ключевое событие или дата, по которой удобно
измерять готовность: релиз 1.0, демо заказчику, конец бета-теста, дедлайн.

**Эпик — это отрезок.** Направление работы, которое тянется во времени
(см. [[epics]]).

Это **две независимые оси**:

| | Эпик | Веха |
|---|---|---|
| Отвечает на вопрос | «что делаем» | «к какому числу» |
| На шкале | полоса | точка (ромб) |
| Состав | задачи одного направления | задачи из **разных** эпиков |
| Задача принадлежит | одному эпику | одной вехе |
| Исполнитель / свой статус | нет / нет | нет / нет |

**Пример.** Задача «Web Push: серверные подписки» входит и в **эпик**
«Уведомления» (про содержание), и в **веху** «Релиз 1.2» (про срок). Обе привязки
живут одновременно.

**У эпика вехи быть не может.** Веха собирает конкретные задачи с общим сроком, а
эпик тянется через несколько релизов сразу — один срок на него повесить нельзя, не
соврав про остальные. Нужен «эпик к дате» — заведите веху и положите в неё те
задачи эпика, что должны попасть в релиз.

## Если вы приходите из другой системы {#migrating}

Короткий ответ для тех, кто мигрирует: веха — это Fix Version / релизная версия,
**не** спринт. Спринтов как отдельной сущности здесь нет.

| Ваш опыт | Здесь |
|---|---|
| Jira: Fix Version, Release | **Веха** |
| GitHub / GitLab: Milestone | **Веха** |
| Jira: Epic | **Эпик** (но без вехи и без исполнителя) |
| Jira: Sprint, GitLab: Iteration | отдельной сущности нет; ближайшая аналогия — веха с датой конца итерации |
| MS Project: веха-событие нулевой длительности | у нас веха — это срок, к которому привязана группа задач |

В Jira и GitLab время разнесено на две оси — спринт/итерация (ритм команды) и
версия/майлстоун (релиз). Здесь ось одна: веха. Меряете релизами — заводите
вехи-релизы; работаете итерациями — вехи с датой конца спринта.

Три отличия сразу:

- у задачи ровно **одна** веха (в Jira их может быть несколько). Бэкпорт в две
  ветки — это два PR, значит и две задачи под свои вехи;
- эпик к вехе **не привязывается**;
- отдельного поля «резолюция» нет — выполненность определяется **закрывающим
  статусом проекта**.

## Где находятся вехи {#where}

Отдельного пункта в верхнем меню нет — вехи всегда про один проект.

**Открыть:** страница **«Проекты»** → в строке проекта нажать иконку-ромб (◆),
рядом с иконками «Дорожная карта» и «База знаний».

## Создание вехи {#create}

На странице вех — кнопка **«+ Веха»**.

| Поле | Обязательно | Примечания |
|---|---|---|
| **Название** | да | Уникально в пределах проекта. |
| **Срок** | да | Веха без даты — просто ярлык. Точной даты нет — поставьте примерную и поправьте потом. |
| **Описание** | нет | Поддерживает [[markdown|Markdown]]. |

Только что созданная веха пустая (0 задач) — это нормально, задачи добавляются
отдельно ([ниже](#add-tasks)).

## Что показывает список вех {#list}

Вехи идут **по возрастанию срока** — ближайший дедлайн сверху.

- **Ромб** слева окрашен по [состоянию](#states). Закрытая — залитый серый ◆,
  открытая — контурный.
- **Полоса прогресса** — доля закрытых задач (`закрыто / всего`), когда задач
  больше одной.
- **`1 просрочена`** — сколько незакрытых задач вехи перешли свой срок
  ([подробно](#overdue)).
- **Дата справа** и **«осталось N дней» / «просрочена на N дней»**.

**Переключатель «Показать закрытые (N)»** — по умолчанию завершённые вехи скрыты.
Появляется, только когда закрытые вехи есть.

## Как добавить задачи в веху {#add-tasks}

Три способа:

1. **Со страницы вехи** — блок «Задачи вехи» → «+ Добавить». Откроется список
   задач проекта **без вехи**. Отметить нужные, «Добавить (N)».
2. **На странице задачи** — сайдбар → селектор **«Веха»** (только открытые вехи
   проекта). Сохраняется сразу. «Без вехи» — отвязать. См. [[task-fields#milestone]].
3. **При создании задачи** — поле «Веха» в форме новой задачи (если у проекта есть
   открытые вехи).

## Состояния вехи {#states}

Состояние **считает сервер** из состава задач и срока — вручную не выставить.
Хранится только «открыта / закрыта».

| Состояние | Что значит | Когда |
|---|---|---|
| **Запланирована** | Работа не начата | Ни одна задача не закрыта |
| **В работе** | Идём по плану | Часть задач закрыта, темп нормальный |
| **Под риском** | Не успеваем по темпу | Дней до срока меньше, чем незакрытых задач |
| **Просрочена** | Срок прошёл, работа осталась | Дата вехи в прошлом, не все задачи закрыты |
| **Готова к закрытию** | Всё сделано, но веха открыта | Все задачи закрыты, человек ещё не закрыл |
| **Закрыта** | Завершена | Веху закрыл человек ([ниже](#close)) |

**«Под риском» — грубый сигнал, не прогноз.** Формула сравнивает число незакрытых
задач с числом дней до срока; трудоёмкость не учитывается — тридцать получасовых
задач за двадцать дней тоже дадут «Под риском». Оценка в часах в расчёт не идёт,
прогресс считается по количеству задач. Воспринимайте это как повод пересмотреть
план.

«1 задача просрочена» в списке — **отдельный индикатор**, не то же самое, что
состояние «Просрочена»: веха может быть «В работе» (свой срок впереди) и содержать
просроченные задачи.

## «N задач просрочено» — что это и как убрать {#overdue}

**Что считается:** задача вехи, у которой одновременно статус **не** закрывающий и
**её собственный** срок в прошлом. Это **не** про срок вехи.

**Иконка ⚠ в списке задач вехи — другое:** она помечает задачи, чей срок **позже**
срока вехи (не успеют по определению).

**Как убрать** — любое из:

1. **Закрыть задачу** — галочка слева от неё в списке «Задачи вехи». Счётчик
   пересчитается сразу.
2. **Подвинуть срок задачи** — открыть задачу → «Срок» → сегодня или позже; либо
   очистить срок совсем.

## Закрытие вехи {#close}

Кнопка **«Закрыть веху»** на странице вехи. **Закрыть можно в любой момент.**

- Незакрытые и просроченные задачи закрытию не мешают. Если такие есть, интерфейс
  спросит подтверждение — это предупреждение, не запрет.
- Единственный отказ — попытка закрыть уже закрытую веху.

**Что с задачами:** не удаляются и никуда не переносятся — остаются привязанными.
Перенести хвост в следующую веху — отдельное действие (селектор «Веха» на каждой
задаче).

**Закрытую веху нельзя пополнять.** Привязать к ней новую задачу не даст ни
интерфейс, ни прямой запрос через API или [[agent|ИИ-агента]] — сервер ответит
«Нельзя добавлять задачи в закрытую веху». Чтобы снова набирать работу — сначала
[откройте веху заново](#reopen).

**Готова к закрытию.** Когда все задачи закрыты, а веху не трогали, появляется
баннер «Все задачи вехи выполнены. Закрыть её?». Система сама веху **не закрывает**
— решение за человеком (релиз может быть собран, но ещё не выпущен).

**Чего система не фиксирует.** После закрытия веха не помечается как «закрыта с
опозданием» — сравнить фактический срок с плановым в интерфейсе нельзя. Событие
остаётся только в журнале активности проекта.

## Открыть веху заново {#reopen}

На странице закрытой вехи — кнопка **«Открыть заново»**. Веха снова активна,
состояние пересчитывается по текущему составу задач.

## Удаление вехи {#delete}

Меню **⋯** на странице вехи → **«Удалить веху»**.

- **Задач нет** — простое подтверждение.
- **Задачи есть** — окно с выбором. **Задачи не удаляются ни при каком варианте:**

  | Вариант | Что происходит |
  |---|---|
  | Открепить задачи и удалить | Задачи остаются в проекте, но без вехи |
  | Перенести задачи и удалить | Выберите другую открытую веху — задачи переедут туда, потом веха удалится |

## Вехи на дорожной карте {#roadmap}

Вехи рисуются **вертикальными линиями с ромбом** поверх полос эпиков, по своим
срокам. Клик по ромбу ведёт на страницу вехи. Смысл — сразу видно, попадает ли
работа эпика в релиз. См. [[roadmap]].

## Вехи в списке задач {#in-task-list}

- **Фильтр «Веха»** (когда выбран проект): «Любая веха» / «Без вехи» / конкретная
  веха.
- **Режим «По вехам»** — задачи проекта сгруппированы по вехам, по возрастанию
  срока, в конце «Без вехи». В строке задачи виден её эпик.

Подробно — [[task-list#views]].

## Типовые сценарии {#scenarios}

**Спланировать релиз.** ◆ → «+ Веха» с датой → открыть → «+ Добавить» задачи из
бэклога → следить за состоянием и числом просроченных.

**Подготовка к демо.** Веха с датой демо → на каждой нужной задаче выставить эту
веху → на [[roadmap|дорожной карте]] проверить, что полосы эпиков заканчиваются
левее ромба → задачи с ⚠ подвинуть или снять с вехи.

**Релиз выехал — перенести хвост.** Незакрытым задачам поставить следующую веху →
исходная становится «Готова к закрытию» → «Закрыть веху».

**Разобрать бэклог.** «Задачи» → проект → фильтр «Веха: Без вехи» → каждой задаче
проставить веху (или оставить без, если это фон).

## Коротко {#tldr}

- Веха = **дата**, эпик = **направление**; у задачи может быть и то, и другое.
- **Срок обязателен**, название уникально в проекте.
- Состояние и прогресс считает система.
- **«Просрочена»** = незакрытая задача со своим сроком в прошлом.
- Закрыть веху можно когда угодно; задачи при этом не пропадают.
- Удаление вехи **никогда не удаляет задачи**.
