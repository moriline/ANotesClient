# Спецификация: менеджер задач «ANotesVue»

**Документ для ИИ-агента и разработчика.** Содержит дизайн-систему, карту экранов, модель данных, поведение компонентов и критерии приёмки. Всё, что здесь описано, реализуемо на указанном стеке без дополнительных зависимостей, кроме явно перечисленных.

Версия: 1.0 · Язык интерфейса: русский · Целевая аудитория: небольшие команды 3–15 человек

---

## 1. Стек и жёсткие ограничения

| Слой | Решение | Версия |
|---|---|---|
| Сборка | Vite | 6+ |
| Фреймворк | Vue 3, `<script setup>`, Composition API | 3.5+ |
| Язык | TypeScript, strict mode | 5.6+ |
| UI | `@nuxt/ui` (Vue-режим, без Nuxt) | 4.11+ |
| Стили | Tailwind CSS v4 (приходит с Nuxt UI) | 4.x |
| Роутинг | `vue-router`, history-режим | 4.x |
| Состояние | Pinia | 3.x |
| Даты | `@internationalized/date` (нужен для `UCalendar`) | — |
| Бэкенд | Java, REST под `/api` | — |

**Запрещено:** Nuxt, SSR, axios, moment.js, отдельные UI-киты поверх Nuxt UI, `localStorage` для доменных данных (только для темы и настроек вида).

**Обязательно:** все компоненты Nuxt UI используются через автоимпорт с префиксом `U`. Не импортировать их вручную.

## 2. Дизайн-направление

Продукт — рабочий инструмент, в котором человек проводит по несколько часов в день. Поэтому: спокойный фон, цвет только там, где он несёт смысл, плотные таблицы, никаких декоративных градиентов и теней «просто так».

Зелёный здесь не украшение, а сигнальная система: он маркирует активное состояние, подтверждающее действие и прогресс. Всё остальное — оттенки серого на белом.

### 2.1 Палитра

Основная шкала — приглушённый лиственный зелёный, не «SaaS-изумруд». Определяется как кастомная палитра Tailwind v4.

```css
/* src/assets/css/main.css */
@import "tailwindcss";
@import "@nuxt/ui";

@theme static {
  /* Основной — moss */
  --color-moss-50:  #F1F7F3;
  --color-moss-100: #DEEDE4;
  --color-moss-200: #BCDBC9;
  --color-moss-300: #90C2A6;
  --color-moss-400: #60A480;
  --color-moss-500: #3E8A61;
  --color-moss-600: #2C6E4B;
  --color-moss-700: #23583D;
  --color-moss-800: #1D4632;
  --color-moss-900: #183A2B;
  --color-moss-950: #0C2119;

  /* Светло-зелёный акцент — sprout. Заливки, теги, прогресс. */
  --color-sprout-50:  #F5FAEC;
  --color-sprout-100: #E9F5D6;
  --color-sprout-200: #D4EBAF;
  --color-sprout-300: #B7DC80;
  --color-sprout-400: #9CCB5B;
  --color-sprout-500: #7FB13F;
  --color-sprout-600: #628C2F;
  --color-sprout-700: #4C6B28;
  --color-sprout-800: #3E5524;
  --color-sprout-900: #354820;
  --color-sprout-950: #1A270D;
}

:root {
  --ui-radius: 0.5rem;
}
```

Привязка семантических алиасов Nuxt UI — в `vite.config.ts` (см. §3).

| Роль | Значение | Где применяется |
|---|---|---|
| `primary` | `moss` | кнопки действия, активный пункт меню, логотип, фокус, чекбоксы, ссылки |
| `secondary` | `sprout` | заливка тегов, шкала прогресса, подсветка «сегодня» в календаре |
| `success` | `moss` | тосты об успехе — намеренно тот же зелёный, отдельный «success-зелёный» рядом с брендовым выглядит грязно |
| `warning` | `amber` | дедлайн сегодня/завтра |
| `error` | `rose` | просрочено, ошибки валидации, удаление |
| `neutral` | `zinc` | текст, границы, фон таблиц |

**Фон приложения — чистый белый `#FFFFFF`.** Не `#FAFAFA`, не тонированный. Разделение зон — только границами `1px solid var(--ui-border)`.

### 2.2 Типографика

**IBM Plex Sans** — интерфейс. **IBM Plex Mono** — идентификаторы задач, даты, числовые колонки таблиц.

Причина выбора функциональная, а не вкусовая: у IBM Plex полноценная кириллица (в отличие от многих гротесков), есть табличные цифры, и моношрифт того же семейства даёт визуальное единство для колонок с `TSK-104`, `12.09.2026`, `4ч 30м`.

```css
@import url('https://fonts.googleapis.com/css2?family=IBM+Plex+Mono:wght@400;500&family=IBM+Plex+Sans:wght@400;500;600&display=swap');

@theme static {
  --font-sans: 'IBM Plex Sans', system-ui, sans-serif;
  --font-mono: 'IBM Plex Mono', ui-monospace, monospace;
}
```

Шкала:

| Роль | Размер / интерлиньяж | Начертание |
|---|---|---|
| Заголовок страницы | 24 / 32 | 600 |
| Заголовок секции, модалки | 18 / 26 | 600 |
| Основной текст, ячейки таблицы | 14 / 20 | 400 |
| Подписи, метаданные, хелперы полей | 13 / 18 | 400, цвет `text-muted` |
| Моно (ID, даты, числа) | 13 / 18 | 400 |

Длина строки описания задачи — не более 76 символов (`max-w-[68ch]`). Заголовки — предложениями, не Title Case, не капслоком.

### 2.3 Правила, которые нельзя нарушать

- Никаких теней, кроме `shadow-sm` на всплывающих слоях (модалка, дропдаун, попап).
- Один радиус скругления `0.5rem` на всём. Исключение: аватары и бейджи статуса — полное скругление.
- Анимации только как ответ на действие: открытие модалки, разворачивание строки, тост. Никаких появлений при скролле.
- Цветом заливается максимум один элемент в зоне видимости на экране просмотра. В таблице цветные только бейджи статуса и теги.
- Иконки — коллекция `lucide`, размер 16px в таблицах и кнопках, 20px в меню.

### 2.4 Смена темы

Тема меняется в одном месте — файл `src/theme.ts`. Требование «цвет можно поменять» реализуется так, чтобы правка была в одной строке.

```ts
// src/theme.ts
export const THEME = {
  primary: 'moss',      // заменить на 'blue' | 'violet' | своя палитра из @theme
  secondary: 'sprout',
  neutral: 'zinc'
} as const
```

Значения подставляются в `vite.config.ts`. Смена палитры на любую другую не должна требовать правок в компонентах: в разметке используются только семантические классы (`bg-primary`, `text-primary`, `border-default`, `bg-elevated`), никаких `bg-moss-500` напрямую.

Тёмная тема в объём первой версии не входит, но семантические классы должны быть выбраны так, чтобы её включение позже не потребовало переписывания разметки.

## 3. Конфигурация проекта

### 3.1 `vite.config.ts`

```ts
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import ui from '@nuxt/ui/vite'
import { fileURLToPath, URL } from 'node:url'
import { THEME } from './src/theme'

export default defineConfig({
  plugins: [
    vue(),
    ui({
      ui: {
        colors: {
          primary: THEME.primary,
          secondary: THEME.secondary,
          neutral: THEME.neutral
        }
      },
      theme: {
        colors: ['primary', 'secondary', 'success', 'warning', 'error']
      },
      colorMode: false,
      experimental: { componentDetection: true }
    })
  ],
  resolve: {
    alias: { '@': fileURLToPath(new URL('./src', import.meta.url)) }
  },
  server: {
    proxy: {
      '/api': { target: 'http://localhost:8080', changeOrigin: true }
    }
  },
  build: {
    outDir: '../src/main/resources/static',
    emptyOutDir: true
  }
})
```

`colorMode: false` — тёмная тема отключена, интеграция `@vueuse/core` не подключается.

`theme.colors` обрезан: `info` не используется, каждый лишний алиас генерирует полный набор оттенков во всех компонентах.

### 3.2 Прочее из документации Nuxt UI (обязательно)

- `src/main.ts`: `app.use(router)`, затем `app.use(ui)`, импорт `main.css` первой строкой.
- `App.vue` обёрнут в `<UApp>` — иначе не работают тосты, тултипы и программные оверлеи.
- `index.html`: `<div id="app" class="isolate">`.
- `package.json`: `"build": "run-s build-only type-check"` — иначе на чистом чекауте `vue-tsc` падает с `Cannot find name 'useToast'`.
- `.gitignore` и `tsconfig.app.json` → `auto-imports.d.ts`, `components.d.ts`.
- `tsconfig.node.json` → алиас `#build/ui` на `./node_modules/.nuxt-ui/ui`.
- Spring Boot: контроллер, отдающий `index.html` на все не-`/api` пути, иначе прямой переход на `/tasks/42` даст 404.

### 4.1 Верхняя панель `AppHeader.vue`

Высота 56px, `sticky top-0 z-50`, фон белый, `border-b border-default`. Внутри — контейнер `max-w-[1440px] mx-auto px-6`.

**Слева — логотип.** Знак: круг диаметром 24px, залитый `bg-primary`, внутри белый росток (иконка `i-lucide-sprout`, 14px). Рядом слово «ANotes» весом 600, размер 16. Кликабелен, ведёт на `/tasks`.

**Центр — навигация.** `UNavigationMenu` с `orientation="horizontal"`, 4 пункта:

| Пункт | Маршрут | Иконка |
|---|---|---|
| Задачи | `/tasks` | `i-lucide-check-square` |
| Проекты | `/projects` | `i-lucide-folder` |
| Теги | `/tags` | `i-lucide-tag` |
| Пользователи | `/people` | `i-lucide-users` |

Активный пункт — текст `text-primary`, вес 500, и подчёркивание `2px bg-primary` вплотную к нижней границе шапки. Никакой заливки фона у активного пункта.

**Справа, в порядке слева направо:**

1. `UInput` поиска, ширина 220px, иконка `i-lucide-search`, плейсхолдер «Поиск задач», справа кбд-хинт `⌘K`. По фокусу или `Cmd/Ctrl+K` открывает командную палитру (§8.1).
2. `UButton` «Задача» с иконкой `i-lucide-plus`, `color="primary"`, `variant="solid"`. Открывает модалку создания задачи. Единственная сплошная зелёная кнопка в шапке.
3. `UDropdownMenu` профиля. Триггер — `UAvatar` 32px с инициалами на `bg-secondary-100 text-secondary-800`, если нет фото. Справа от аватара — `i-lucide-chevron-down` 14px.

Пункты меню профиля:

| Пункт | Действие |
|---|---|
| Имя пользователя + email | не кликабельный заголовок группы |
| Мой профиль | `router.push('/profile')` |
| Настройки уведомлений | модалка |
| — | разделитель |
| Выйти | `POST /api/auth/logout`, затем `/login` |

**Адаптив:** ниже 1024px навигация сворачивается в `USlideover`, открываемый кнопкой-бургером слева. Поиск превращается в иконку. Кнопка «Задача» — только иконка `+`. Аватар остаётся.

## 5. Карта маршрутов

Правило разделения: **отдельная страница — там, где человек работает долго и может прислать ссылку коллеге. Модалка — там, где действие занимает меньше минуты.**

```ts
const routes = [
  { path: '/',                redirect: '/tasks' },
  { path: '/login',           component: LoginView,       meta: { public: true, chrome: false } },
  { path: '/tasks',           component: TaskListView,    name: 'tasks' },
  { path: '/tasks/:id',       component: TaskDetailView,  name: 'task', props: true },
  { path: '/projects',        component: ProjectListView, name: 'projects' },
  { path: '/tags',            component: TagListView,     name: 'tags' },
  { path: '/people',          component: PeopleListView,  name: 'people' },
  { path: '/profile',         component: ProfileView,     name: 'profile' },
  { path: '/:pathMatch(.*)*', component: NotFoundView }
]
```

| Что | Где | Почему |
|---|---|---|
| Редактирование задачи | **страница** `/tasks/:id` | длинное описание, комментарии, история, вложения; ссылкой делятся |
| Профиль пользователя | **страница** `/profile` | несколько блоков настроек, редко открывается, не должен теряться при перезагрузке |
| Создание задачи | модалка | быстрый ввод, не должен уводить с текущего списка |
| Проект: создание и правка | модалка | 5 полей |
| Тег: создание и правка | модалка | 3 поля |
| Пользователь: приглашение и правка роли | модалка | 4 поля |
| Подтверждение удаления | модалка | всегда |
| Настройки уведомлений | модалка | переключатели |

Модалки **не отражаются в URL** и не добавляются в историю браузера. Закрытие по `Esc` и клику вне области. При наличии несохранённых изменений `Esc` перехватывается и показывается подтверждение «Закрыть без сохранения?».

Переход на `/tasks/:id` сохраняет параметры фильтров списка в query, чтобы кнопка «Назад к списку» возвращала к тому же состоянию: `/tasks?status=open&project=3`.

## 6. Модель данных

Файл `src/types/domain.ts`. Все API-ответы типизируются этими интерфейсами.

```ts
export type TaskStatus   = 'backlog' | 'todo' | 'in_progress' | 'review' | 'done' | 'cancelled'
export type TaskPriority = 'low' | 'normal' | 'high' | 'urgent'
export type UserRole     = 'owner' | 'admin' | 'member' | 'viewer'

export interface Task {
  id: number
  key: string                 // 'TSK-104' — отображается моношрифтом
  title: string
  description: string         // Markdown
  status: TaskStatus
  priority: TaskPriority
  projectId: number | null
  assigneeId: number | null
  reporterId: number
  tagIds: number[]
  dueDate: string | null      // ISO 'YYYY-MM-DD'
  estimateMinutes: number | null
  spentMinutes: number
  createdAt: string           // ISO 8601
  updatedAt: string
  version: number             // optimistic locking, шлётся обратно в PUT
}

export interface Project {
  id: number
  key: string                 // 'WEB' — префикс ключей задач
  name: string
  description: string
  ownerId: number
  color: string               // hex, для точки-маркера в списках
  archived: boolean
  taskCount: number           // считает сервер
  openTaskCount: number
  createdAt: string
}

export interface Tag {
  id: number
  name: string
  color: string               // hex
  description: string
  usageCount: number          // считает сервер
}

export interface User {
  id: number
  email: string
  fullName: string
  avatarUrl: string | null
  role: UserRole
  active: boolean
  timezone: string            // IANA, 'Europe/Kyiv'
  lastSeenAt: string | null
  createdAt: string
}

export interface Comment {
  id: number
  taskId: number
  authorId: number
  body: string                // Markdown
  createdAt: string
  editedAt: string | null
}

export interface Page<T> {
  items: T[]
  total: number
  page: number
  size: number
}
```

## 7. Экраны

### 7.1 `/tasks` — список задач

Главный экран. Открывается по умолчанию.

**Панель фильтров** (одна строка над таблицей, `gap-2`):

| Контрол | Компонент | Поведение |
|---|---|---|
| Поиск по названию | `UInput` с `i-lucide-search`, 240px | debounce 300 мс |
| Статус | `USelectMenu` multiple | по умолчанию исключены `done` и `cancelled` |
| Проект | `USelectMenu` с поиском | точка цвета проекта слева от названия |
| Исполнитель | `USelectMenu` с аватарами | есть опция «Не назначен» |
| Теги | `USelectMenu` multiple | |
| Сброс | `UButton variant="ghost"` | появляется, только если активен хотя бы один фильтр |

Состояние фильтров синхронизируется с query-параметрами URL.

**Таблица** `UTable`, `sticky` заголовок:

| Колонка | Ширина | Содержимое |
|---|---|---|
| ☐ | 40 | чекбокс выбора строки |
| Ключ | 90 | `TSK-104`, моно, 13px, `text-muted` |
| Название | flex | текст 14px; при наведении подчёркивание; ниже — теги, если есть |
| Статус | 130 | `UBadge` subtle с иконкой |
| Приоритет | 110 | `UBadge` только для `high` и `urgent` |
| Исполнитель | 160 | `UAvatar` 24px + имя; «Не назначен» серым курсивом |
| Срок | 120 | `12 сен`; сегодня — `text-warning`, просрочено — `text-error` + `i-lucide-alert-circle` |
| Обновлена | 120 | относительное время «2 ч назад», тултип с точной датой |
| ⋯ | 48 | `UDropdownMenu` действий строки |

Клик по строке (кроме чекбокса и меню) → `/tasks/:id`.

**Меню действий строки:** Открыть · Изменить статус (подменю) · Назначить на себя · Дублировать · — · Удалить (`color="error"`).

**Массовые действия.** При выборе ≥1 строки над таблицей появляется полоса: «Выбрано: 3» + кнопки «Сменить статус», «Назначить», «Добавить тег», «Удалить». Полоса вытесняет панель фильтров, а не добавляется к ней.

**Пустые состояния:**

- Нет задач вообще: иконка `i-lucide-sprout` 40px `text-primary`, «Пока ни одной задачи», подпись «Создайте первую — она появится здесь», кнопка «Создать задачу».
- Фильтры ничего не нашли: «Ничего не найдено», подпись «Попробуйте изменить фильтры», кнопка «Сбросить фильтры».

**Загрузка:** скелетон из 8 строк таблицы, а не спиннер по центру.

**Пагинация:** `UPagination` снизу справа, 25 строк на странице. Слева — «Показано 25 из 143».

### 7.2 `/tasks/:id` — задача (отдельный маршрут)

Двухколоночный макет, `max-w-[1200px]`.

```

TSK-104  ·  WEB                                  [Готово ▾]  [⋯]
┌──────────────────────────────────────┐  ┌──────────────────────┐
│ Заголовок (редактируется по клику)   │  │ Статус     [select]  │
│                                      │  │ Исполнитель [select] │
│ Описание                             │  │ Приоритет   [select] │
│ ┌──────────────────────────────────┐ │  │ Проект      [select] │
│ │ Markdown, редактируется по клику │ │  │ Срок        [date]   │
```

**Инлайн-редактирование.** Заголовок и описание редактируются по клику прямо на месте: превращаются в `UTextarea`/`UInput` с кнопками «Сохранить» и «Отмена». Отдельного режима редактирования у страницы нет.

**Описание** рендерится как Markdown в режиме просмотра (`marked` + `dompurify`). WYSIWYG не используется: хранится текст, а не HTML.

**Конфликт версий.** Если `PUT` вернул `409`, показать модалку: «Задачу изменил другой пользователь», с кнопками «Перезагрузить» и «Перезаписать». Поле `version` из ответа.

**Комментарии:** аватар 28px, имя, относительное время, тело в Markdown. Своё сообщение можно править и удалять в течение сессии. Поле ввода внизу, `Cmd/Ctrl+Enter` отправляет.

**Меню `⋯` в шапке:** Дублировать · Копировать ссылку · — · Удалить задачу.

**Если задача не найдена** — `NotFoundView` с текстом «Задача не найдена» и ссылкой на список, а не пустая страница.

## 8. Модальные окна

Все модалки — `UModal`. Общие правила:

- Заголовок 18/26 весом 600, без подзаголовка, если он не несёт информации.
- Футер: кнопки справа, «Отмена» (`variant="ghost"`) слева от основной.
- Основная кнопка — `color="primary"`, при удалении — `color="error"`.
- Кнопка отправки показывает `loading` и блокируется на время запроса.
- Валидация — `UForm` + Zod-схема, ошибки под полями, не тостом.
- После успеха: модалка закрывается, список обновляется, тост подтверждения.
- Ширина: `sm` (400px) для подтверждений, `md` (560px) для форм, `lg` (720px) для создания задачи.

### 8.1 Командная палитра (`Cmd/Ctrl+K`)

`UModal` + `UCommandPalette`. Группы:
1. **Задачи** — поиск по названию и ключу, до 6 результатов, переход на `/tasks/:id`.
2. **Переход** — Задачи, Проекты, Теги, Пользователи, Мой профиль.
3. **Действия** — Создать задачу, Создать проект, Создать тег.

### 8.2 Создание задачи (`lg`)

Поля: Название (обязательно, автофокус) · Описание (`UTextarea`, 4 строки, Markdown) · Проект · Исполнитель · Приоритет (по умолчанию «Обычный») · Срок · Теги.

Футер слева — `UCheckbox` «Создать ещё одну»: если включён, после сохранения модалка не закрывается, поля очищаются, фокус возвращается на название.

`Cmd/Ctrl+Enter` = сохранить.

### 8.3 Проект (`md`)

Ключ (3–5 заглавных латинских букв, `uppercase`, проверка уникальности на blur) · Название · Описание · Владелец · Цвет (палитра из 8 предустановленных кружков).

При редактировании ключ `disabled` с подписью «Ключ нельзя изменить после создания».

### 8.4 Тег (`md`)

Название (уникальное) · Цвет (те же 8 кружков) · Описание. Над футером — живое превью бейджа.

### 8.5 Приглашение и правка пользователя (`md`)

Приглашение: Email · Полное имя · Роль (`URadioGroup` с описанием каждой роли одной строкой). Кнопка «Отправить приглашение».

Правка: имя и роль. Email `disabled`.

### 8.6 Подтверждение удаления (`sm`)

Универсальный компонент `ConfirmDialog.vue`.

- Заголовок: «Удалить задачу TSK-104?» — всегда с именем объекта.
- Тело: последствия конкретно. «Задача и все комментарии к ней будут удалены. Это действие нельзя отменить.»
- Кнопки: «Отмена» · «Удалить» (`color="error"`).
- Для объектов со связями — предупреждение о количестве затронутых сущностей.

## 10. Контракт API

Базовый путь `/api`. Всё возвращает JSON. Аутентификация — HttpOnly cookie-сессия.

```
POST   /api/auth/login          { email, password } → User
POST   /api/auth/logout         → 204
GET    /api/auth/me             → User

GET    /api/tasks               ?page&size&q&status[]&projectId&assigneeId&tagId[]&sort → Page<Task>
POST   /api/tasks               → Task
GET    /api/tasks/{id}          → Task
PUT    /api/tasks/{id}          → Task           (409 при конфликте version)
DELETE /api/tasks/{id}          → 204
POST   /api/tasks/bulk          { ids[], patch } → 204

GET    /api/tasks/{id}/comments → Comment[]
POST   /api/tasks/{id}/comments → Comment
PUT    /api/comments/{id}       → Comment
DELETE /api/comments/{id}       → 204

GET    /api/projects            ?includeArchived → Project[]
POST   /api/projects            → Project
PUT    /api/projects/{id}       → Project
DELETE /api/projects/{id}       → 204

GET    /api/tags                → Tag[]
POST   /api/tags                → Tag
PUT    /api/tags/{id}           → Tag
DELETE /api/tags/{id}           → 204

GET    /api/users               → User[]
POST   /api/users/invite        → User
PUT    /api/users/{id}          → User
DELETE /api/users/{id}          → 204

GET    /api/profile             → User
PUT    /api/profile             → User
PUT    /api/profile/password    { current, next } → 204
POST   /api/profile/avatar      multipart → { avatarUrl }
```

### 10.1 Формат ошибки

```json
{
  "message": "Проект с ключом WEB уже существует",
  "field": "key",
  "code": "DUPLICATE_KEY"
}
```

Клиент показывает `message` под полем `field`, если оно указано, иначе — тостом.

### 10.2 Слой доступа

Единственная обёртка `src/api/http.ts` поверх нативного `fetch`. Не axios.

```ts
export async function http<T>(url: string, init?: RequestInit): Promise<T> {
  const res = await fetch(`/api${url}`, {
    credentials: 'include',
    headers: { 'Content-Type': 'application/json', ...init?.headers },
    ...init
  })
  if (res.status === 401) { router.push('/login'); throw new UnauthorizedError() }
  if (!res.ok) throw new ApiError(await res.json().catch(() => ({ message: res.statusText })))
  return res.status === 204 ? (undefined as T) : res.json()
}
```

## 14. Микрокопия

Правила: предложениями, не капслоком. Кнопка называет результат, а не процесс. Действие сохраняет своё имя во всей цепочке — кнопка «Удалить» → подтверждение «Удалить» → тост «Удалено». Ошибки не извиняются и не бывают расплывчатыми.

| Плохо | Хорошо |
|---|---|
| Submit | Создать задачу |
| Что-то пошло не так | Не удалось сохранить: проект уже удалён |
| Нет данных | Пока ни одной задачи |
| Are you sure? | Удалить проект «Веб-клиент»? |
| Успешно! | Задача создана |
| Введите корректное значение | Название не может быть пустым |
