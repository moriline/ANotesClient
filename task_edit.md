# Модель сохранения данных на странице задачи

Экран `/tasks/:projectId/:taskId` — `src/views/TaskDetailView.vue`.

Граница проходит по **дискретный выбор против длинного текста** (`task_edit_2.md`),
а не «поля задачи против остального».

---

## 1. Пикеры — сохраняются сразу

Статус, исполнитель, срок, дата начала, оценка (ч), теги, а также
архивировать/восстановить. Выбор в `USelectMenu` — уже принятое решение,
подтверждать его отдельной кнопкой незачем.

- селектор / инпут привязан к `task.value.*` (`:model-value`), `@update:model-value`
  / `@change` вызывает `saveField(patch)`;
- `saveField` — оптимистично (локально применяет `patch` к `task.value`), затем
  `PATCH /api/projects/{pid}/tasks/{tid}` с `X-Expected-Version = task.version`;
  при ошибке — откат к прежнему `task.value`;
- **очередь `saveQueue`**: правки уходят по одной. Быстрые «сначала статус, потом
  исполнитель» не ловят ложный `409` из-за гонки версий между собой;
- `savingField` — имя поля в полёте, для индикатора `:loading` у селектора.

## 2. Название и описание — правятся явно

`InlineEdit` (клик → редактор → «Готово»). «Готово» коммитит **прямо на сервер**
(`saveTitle` / `saveDescription` → тот же `saveField`), промежуточной формы нет.

- **черновик**: пока открыт редактор описания, текст раз в секунду пишется в
  `sessionStorage` (`draft-key` = `taskmind.taskDraft.desc.<id>`; при
  размонтировании — финальная дозапись). При возврате на задачу над редактором
  строка «Несохранённый черновик от 14:32 · [Восстановить] [Отбросить]».
  `sessionStorage`, не `localStorage`: черновик недельной давности вреднее его
  отсутствия;
- у названия черновика нет (однострочное, правка — секунды).

## 3. Чего больше нет

| Убрано | Заменено на |
|---|---|
| Липкая плашка «Есть несохранённые изменения» + кнопка «Сохранить» | пикеры сохраняются сразу; название/описание — по «Готово» |
| `onBeforeRouteLeave` («Уйти без сохранения?») | черновик в `sessionStorage` |
| `beforeunload` | черновик в `sessionStorage` |
| `Ctrl/⌘+S` | нечего сохранять глобально |

## 4. Конфликты (`409`)

Версия по-прежнему сравнивается **по всей задаче**, поэтому часть `409` ложные
(правили разные поля). Полевой конфликт — серверная работа (`task_edit_2.md`
пп. 3–5), клиентом не закрывается. Пока:

- `saveField` на `409` откатывает оптимистичное применение и показывает диалог
  **«Записать поверх / Перезагрузить»** (`askOverwriteOnConflict`);
- «Записать поверх» → повтор `PATCH` без заголовка версии (last-write-wins по
  одному полю);
- «Перезагрузить» / отмена → `reloadTask()` перечитывает задачу.

## 5. Всё остальное — как было, каждое своей ручкой

| Действие | Ручка | Версия |
|---|---|---|
| Эпик задачи (`changeParent`) | `PUT /api/tasks/{id}/parent` | нет (в контракте нет `X-Expected-Version`) |
| Преобразовать задача ↔ эпик (`convertType`, после confirm) | `PUT /api/tasks/{id}/convert` | нет |
| Комментарии | `POST` / `PATCH` / `DELETE /api/tasks/{id}/comments…` | нет |
| Резюме (AI) | своя `UTextarea` + своя кнопка → `PUT /api/tasks/{id}/summary` | нет (version не меняется) |
| Учёт времени | `logTime` / `deleteTimeEntry` | нет |
| Файлы | `uploadTaskFile` / `deleteFile` | нет |
| Чекбоксы задач эпика (`EpicTaskList.vue`) | оптимистично с откатом; `PATCH` статуса **дочерней** задачи с её `X-Expected-Version`; `emit('changed')` → родитель `getTask` за прогрессом | да (у дочерней) |
