# ANotes — доска: отображение задач по статусу

Третий режим просмотра списка задач: колонки по статусам вместо плоской таблицы и вместо групп по эпикам. Дополняет `tasks_view.md` (группировка по эпикам) и `parent_task.md` (модель EPIC/TASK).

Стек: Vue 3 + TypeScript + Nuxt UI. **Серверных изменений не требует ни одного.**

---

## 1. Почему это режим вида, а не новая функция

Список уже умеет два режима — плоская таблица и группы по эпикам. Группировка по `statusId` это тот же клиентский код с другим ключом; отрисовать группы колонками вместо стопки — вопрос вёрстки, не данных.

Всё, что нужно доске, сервер уже отдаёт:

| Что нужно доске | Откуда берётся | Готово |
|---|---|---|
| Колонки, их порядок, цвет | `GET /api/project-statuses/project/{id}` — `statusOrder`, `statusColor` | да |
| Какая колонка входная / закрывающая / скрытая | там же — `isDefault`, `isClosed`, `isHidden` | да |
| Карточки со `statusId` | `POST /api/find` → `TaskResponse.statusId` | да |
| Загрузка всего проекта разом, без пагинации | `POST /api/find` с `grouped: true` | да |
| Перенос карточки между колонками | `PATCH /api/projects/{projectId}/tasks/{taskId}` со `statusId` | да |
| Защита от одновременного перетаскивания | `X-Expected-Version` + конфликт по полю (`task_edit_2.md`) | да |
| **Порядок карточек внутри колонки** | — | **нет**, см. §3.3 |

Переключатель вида — тот же, что в `tasks_view.md` §6.4, третьим пунктом:

```ts
const viewMode = ref<'list' | 'epic' | 'board'>('list')
```

## 2. Запросы

### 2.1 Колонки

```
GET /api/project-statuses/project/{projectId}
```

```json
[
  { "id": 1, "projectId": 7, "statusName": "To Do",       "statusColor": "#95A5A6",
    "statusOrder": 0, "isDefault": true,  "isClosed": false, "isHidden": false },
  { "id": 2, "projectId": 7, "statusName": "In Progress", "statusColor": "#3498DB",
    "statusOrder": 1, "isDefault": false, "isClosed": false, "isHidden": false },
  { "id": 3, "projectId": 7, "statusName": "Done",        "statusColor": "#2ECC71",
    "statusOrder": 2, "isDefault": false, "isClosed": true,  "isHidden": false }
]
```

Сервер уже отдаёт по `statusOrder`. Скрытые колонки приходят в списке (они нужны в настройках доски), но на доске не рисуются:

```ts
const columns = computed(() => statuses.value.filter(s => !s.isHidden))
const closedColumn = computed(() => columns.value.find(s => s.isClosed))
```

### 2.2 Карточки рабочих колонок

```
POST /api/find
{ "projectId": 7, "grouped": true, "sortBy": "dueDate", "sortDir": "asc" }
```

`grouped: true` — весь проект разом, без пагинации. Требует `projectId` (иначе 400); если подходящих задач больше `taskmind.tasks.grouping-hard-limit` (по умолчанию 5000) — тоже 400 с внятным текстом, а не сорок мегабайт (`tasks_view.md` §8).

Ответ: `{ tasks: TaskResponse[], total, limit, offset }`. В `limit` придёт размер выдачи, в `offset` — 0: страниц нет.

### 2.3 Карточки закрывающей колонки — отдельным запросом

```
POST /api/find
{ "projectId": 7, "statusId": 3, "limit": 20, "sortBy": "updatedAt", "sortDir": "desc" }
```

Почему отдельным — см. §3.1.

### 2.4 Перенос карточки

```
PATCH /api/projects/{projectId}/tasks/{taskId}
X-Expected-Version: 4
{ "statusId": 2 }
```

`200` → обновлённый `TaskResponse` (в нём новый `version`).
`409` → `FieldConflictResponse`:

```json
{
  "message": "Поля изменены другим пользователем: [statusId]",
  "currentVersion": 5,
  "conflicts": [{
    "field": "statusId",
    "theirValue": 3,
    "theirAuthor": "Анна",
    "theirChangedAt": "2026-09-08T07:41:12Z",
    "yourValue": 2
  }]
}
```

Заголовок `X-Expected-Version` необязателен, но на доске его стоит слать всегда: перетаскивание — самое частое место, где два человека трогают одну карточку одновременно.

## 3. Три камня

Все три — клиентские. Ни один не требует правки сервера.

### 3.1 Колонка «Готово» приедет пустой

`grouped: true` возвращает всё **незакрытое**: задачи в статусе с `isClosed = TRUE` он отсекает намеренно (`tasks_view.md` §8). Если построить доску на одном этом запросе, закрывающая колонка будет пустой всегда.

Лечится вторым дешёвым запросом (§2.3) — и так и надо:

```ts
const [board, done] = await Promise.all([
  http('/api/find', { method: 'POST', body: { projectId, grouped: true,
                                              sortBy: 'dueDate', sortDir: 'asc' } }),
  closedColumn.value
    ? http('/api/find', { method: 'POST', body: { projectId, statusId: closedColumn.value.id,
                                                  limit: 20, sortBy: 'updatedAt', sortDir: 'desc' } })
    : Promise.resolve({ tasks: [], total: 0 })
])
```

Доска, показывающая все когда-либо сделанные задачи, бесполезна — через полгода «Готово» это тысяча карточек, которые никто не листает. Поэтому в заголовке колонки честно пишем, что показана верхушка:

```
Готово   20 из 347
```

`total` из второго ответа даёт «347» бесплатно.

### 3.2 Эпики приедут без статуса

`grouped: true` отдаёт **все эпики проекта** — они нужны для заголовков групп в режиме «по эпикам». У эпика `statusId = null` по построению (`parent_task.md`: эпик нельзя выполнять, у него нет своего статуса). На доске они осели бы в фантомную колонку «без статуса».

```ts
const cards = computed(() => board.value.tasks.filter(t => t.taskType !== 'EPIC'))
```

Обратная сторона, с которой надо согласиться сознательно: **эпиков на доске не будет вообще.** Это правильно — эпик контейнер, а не работа, — но человек, привыкший видеть на доске всё, спросит. Ответ на его вопрос: эпики живут в режиме «по эпикам», а на доске видна их начинка. Если хочется связи — покажите `parentTitle` мелким шрифтом на карточке, он уже приходит в `TaskResponse`.

### 3.3 Порядка карточек внутри колонки нет

Сервер не хранит позицию задачи. Следствия два:

- Порядок в колонке — это `sortBy` из запроса. При `updatedAt desc` любая правка карточки поднимает её наверх: перетащил — прыгнула.
- Перетащить карточку **внутри** колонки нельзя вообще. Сохранять нечего.

Насколько это мешает — зависит от того, как доской пользуются:

| Как используют доску | Порядок нужен? |
|---|---|
| «Покажи, что в каком состоянии» — обзор | **нет.** Сортировка по сроку даёт честный, полезный порядок |
| «Верх колонки To Do — то, что делаем следующим» — приоритизация | **да**, иначе доска врёт |

Небольшие команды почти всегда пользуются первым способом.

**Решение: не заводить `position`, пока использование не докажет, что он нужен.** Через две недели работы вы будете знать ответ, который сейчас можно только угадать. Не попросили перетаскивать внутри колонки — вы сэкономили вечер и класс многопользовательских багов. Попросили — вечер никуда не делся (эскиз в §8).

Пока порядка нет, перетаскивание внутри колонки надо **запретить**, а не делать вид, что оно работает: карточка, вернувшаяся на место после отпускания мыши, читается как поломка.

```ts
// vuedraggable: перенос между списками разрешён, сортировка внутри — нет
:group="{ name: 'board', pull: true, put: true }"
:sort="false"
```

## 4. Сортировка по умолчанию — по сроку, не по правке

`updatedAt desc` (умолчание `/api/find`) на доске читается как «сверху то, что последним трогали» — это шум, а не порядок. `dueDate asc` читается как «сверху то, что горит», и это осмысленный порядок, который не требует `position`.

```
{ "sortBy": "dueDate", "sortDir": "asc" }
```

Допустимые значения `sortBy`: `createdAt`, `updatedAt`, `dueDate`, `title`. Задачи без срока при `asc` уйдут в конец колонки — это то, что нужно.

## 5. Сборка доски

```ts
// composables/useStatusBoard.ts
export interface BoardColumn {
  status: ProjectStatusResponse
  cards: TaskResponse[]
  total: number          // сколько всего в колонке; у закрывающей больше, чем показано
}

export function useStatusBoard(
  statuses: Ref<ProjectStatusResponse[]>,
  cards: Ref<TaskResponse[]>,
  doneCards: Ref<TaskResponse[]>,
  doneTotal: Ref<number>
) {
  return computed<BoardColumn[]>(() =>
    statuses.value
      .filter(s => !s.isHidden)
      .map(s => {
        if (s.isClosed) {
          return { status: s, cards: doneCards.value, total: doneTotal.value }
        }
        const own = cards.value.filter(t => t.statusId === s.id)
        return { status: s, cards: own, total: own.length }
      })
  )
}
```

Задачи со `statusId === null` (проекты, заведённые до появления статусов по умолчанию) не попадут ни в одну колонку и молча исчезнут. Если такие проекты есть — добавьте служебную колонку «Без статуса» в конец; если нет — не усложняйте.

## 6. Перенос карточки: оптимистично, с откатом и разбором 409

```ts
async function moveCard(task: TaskResponse, toStatusId: number) {
  const from = task.statusId
  task.statusId = toStatusId                       // оптимистично: карточка едет сразу

  try {
    const updated = await http(`/api/projects/${task.projectId}/tasks/${task.id}`, {
      method: 'PATCH',
      headers: { 'X-Expected-Version': String(task.version) },
      body: { statusId: toStatusId }
    })
    Object.assign(task, updated)                   // забираем новый version
  } catch (e: any) {
    task.statusId = from                           // откат
    if (e.status === 409) {
      const c = e.data.conflicts.find((x: any) => x.field === 'statusId')
      toast.add({
        title: `${c.theirAuthor} уже перенёс эту карточку`,
        description: 'Доска обновлена — попробуйте снова',
        color: 'warning'
      })
      await refreshBoard()                         // подтягиваем чужую правку
    } else {
      toast.add({ title: 'Не удалось перенести карточку', color: 'error' })
    }
  }
}
```

Три вещи, без которых будет плохо:

- **`X-Expected-Version` берётся у карточки, а не у доски.** Версия принадлежит задаче; на доске её легко забыть передать.
- **`Object.assign(task, updated)`** — без этого `version` останется старым, и следующее перетаскивание той же карточки даст ложный 409.
- **Откат до обновления доски.** Сначала вернуть карточку на место, потом перезапросить: иначе на секунду видно два состояния сразу.

## 7. Чего добавлять на сервере не нужно

| | Почему |
|---|---|
| Эндпоинт доски | колонки и карточки — два уже существующих запроса |
| `position` у задачи | см. §3.3 — сначала выясните, нужен ли |
| Счётчики по колонкам | `cards.length`, а для закрывающей — `total` из ответа |
| Хранение выбранного режима вида | `sessionStorage`, как состояние сворачивания в `tasks_view.md` §4 |
| Новый фильтр «только доска» | доска — это тот же `grouped: true` |

## 8. Если порядок всё-таки понадобится

Эскиз, чтобы решение осталось обратимым, а не превратилось в переписывание:

- `tasks.position INTEGER NOT NULL DEFAULT 0` + индекс `(statusId, position)`;
- целочисленная позиция со сдвигом соседей (`UPDATE tasks SET position = position + 1 WHERE statusId = ? AND position >= ?`), **не** разреженные ранги: LexoRank и дробные позиции — оптимизация под нагрузку, которой здесь не будет, ценой класса багов «карточки поменялись местами сами»;
- отдельная ручка `PUT /api/tasks/{taskId}/board-position` с телом `{ statusId, position }`, а не поле в PATCH: перенос меняет `statusId` и `position` вместе и затрагивает соседние строки, которых `version` не покрывает — та же причина, по которой `PUT /api/tasks/{id}/parent` сделан отдельной ручкой;
- `TaskSortField.POSITION` и позиция в хвосте колонки у новой задачи.

Сервер — один вечер, 6–8 часов вместе с тестами. Клиент — плюс сортировка внутри списков (`:sort="true"`).

## 9. Порядок работ

**Вечер 1.** Переключатель вида третьим пунктом, `useStatusBoard`, колонки, карточка. Два запроса из §2.2 и §2.3, фильтр эпиков, сортировка по сроку. Доска уже читается.

**Вечер 2.** Перетаскивание между колонками с оптимистичным обновлением, откатом и разбором 409. Сортировка внутри колонок выключена (§3.3).

**Вечер 3.** Заголовки колонок со счётчиками и «20 из 347», сворачивание закрывающей колонки, пустые состояния, `sessionStorage` для выбранного режима вида.

## 10. Тесты

Серверных тестов не добавляется — серверного кода не добавляется. Клиентские:

| Сценарий | Что проверяет |
|---|---|
| `useStatusBoard` | карточки раскладываются по `statusId`; скрытые колонки не рисуются; порядок колонок по `statusOrder` |
| — эпики | `taskType === 'EPIC'` не попадает ни в одну колонку |
| — закрывающая колонка | берёт карточки из отдельного ответа, показывает `total`, а не `cards.length` |
| — задача без статуса | не исчезает молча (либо служебная колонка, либо явное решение её не показывать) |
| `moveCard` | оптимистичный перенос; откат при ошибке; `version` обновляется из ответа |
| — 409 | карточка возвращается на место, показывается имя из `theirAuthor`, доска перезапрашивается |
| Перетаскивание | внутри колонки запрещено (`:sort="false"`), между колонками разрешено |
