# ANotes — клиентское демо на GitHub Pages

Инструкция для ИИ-агента: собрать работающее демо интерфейса **без бэкенда**, задеплоить на GitHub Pages, дать ссылку для README.

Результат: `https://<username>.github.io/<repo>/` — приложение кликается целиком, данные живут в памяти вкладки, перезагрузка возвращает исходное состояние.

Ориентир — Planka, у которой в README стоит ссылка «Client demo (without server features)».

---

## 0. Правила работы

**Не ломать боевое приложение.** Демо — отдельный режим сборки. Ни один существующий компонент, вью или стор не должен узнать о том, что он работает в демо. Единственная точка подмены — транспортный слой.

**Не трогать `src/api/*.ts`, кроме `http.ts`.** Функции-обёртки (`getTask`, `updateTask`, `findTasks` и прочие) остаются как есть: они вызывают `http()`, а уже он в демо-режиме возвращает данные из памяти.

**Проверять после каждого шага.** `npm run dev` с флагом демо должен работать локально до того, как вы дойдёте до деплоя.

**Если упрётесь в неизвестное** — например, неясна форма ответа какой-то ручки — берите её из `openapi5.yaml`, а не выдумывайте.

```bash

```

Прочитать `src/api/http.ts` целиком. Нужно понять:

## 2. Переключатель режима

### 2.1 Переменная окружения

Создать `.env.demo`:

```
VITE_DEMO=true
VITE_BASE=/anotes/
```

`VITE_BASE` — имя репозитория со слешами с обеих сторон. Для `username.github.io/anotes` это `/anotes/`. Если репозиторий называется `username.github.io`, то просто `/`.

### 2.2 Скрипты

В `package.json` **добавить**, ничего не заменяя:

```json
{
  "scripts": {
    "dev:demo": "vite --mode demo",
    "build:demo": "vite build --mode demo && vue-tsc -b"
  }
}
```

### 2.3 `vite.config.ts`

Добавить `base`, читаемый из окружения. Существующий `server.proxy` не трогать — в демо-режиме он просто не используется.

```ts
export default defineConfig(({ mode }) => {
  const env = loadEnv(mode, process.cwd(), '')
  return {
    base: env.VITE_BASE || '/',
    // ...всё остальное без изменений
  }
})
```

### 2.4 Роутер

GitHub Pages не умеет history-режим: прямой переход на `/tasks/1/42` даст 404. Два решения, взять **первое**:

**Вариант А (рекомендуется) — хеш-роутер только в демо:**

```ts
// src/router/index.ts
import { createRouter, createWebHistory, createWebHashHistory } from 'vue-router'

const history = import.meta.env.VITE_DEMO === 'true'
  ? createWebHashHistory(import.meta.env.BASE_URL)
  : createWebHistory(import.meta.env.BASE_URL)

export default createRouter({ history, routes })
```

Адреса станут вида `/anotes/#/tasks/1/42` — некрасиво, но работает без единого костыля.

**Вариант Б** — копия `index.html` в `404.html` при сборке. Работает, но ломает предпросмотр ссылок и путает поисковики. Брать, только если человек настаивает на чистых адресах.

## 3. Демо-транспорт

### 3.1 Где подменять

**Только в `http.ts`**, первой строкой:

```ts
// src/api/http.ts
import { demoHttp } from './demo/demoHttp'

export async function http<T>(url: string, init?: RequestInit): Promise<T> {
  if (import.meta.env.VITE_DEMO === 'true') {
    return demoHttp<T>(url, init)
  }
  // ...существующая реализация без изменений
}
```

Одна ветка — и весь остальной код приложения не знает о демо.

### 3.2 Структура

```
src/api/demo/
├─ demoHttp.ts      маршрутизатор: путь + метод → обработчик
├─ store.ts         состояние в памяти (reactive)
├─ seed.ts          генерация данных со сдвигом от сегодня
├─ handlers/
│  ├─ auth.ts       login, agent-token, users/me
│  ├─ projects.ts   проекты, статусы, участники, теги
│  ├─ tasks.ts      задачи, find, комментарии, время, активность
│  ├─ epics.ts      эпики, прогресс, convert, parent
│  ├─ milestones.ts вехи
│  ├─ roadmap.ts    дорожная карта
│  └─ wiki.ts       страницы, дерево, ревизии
└─ util.ts          задержка, пагинация, ошибки
```

### 3.3 Маршрутизатор

```ts
// src/api/demo/demoHttp.ts
type Handler = (ctx: Ctx) => unknown | Promise<unknown>

interface Ctx {
  params: Record<string, string>
  query: URLSearchParams
  body: any
  headers: Record<string, string>
}

const routes: Array<[string, string, Handler]> = [
  ['POST',  '/auth/login',                        login],
  ['GET',   '/tasks/:taskId',                     getTask],
  ['PATCH', '/tasks/:taskId',                     patchTask],
  // ...
]

export async function demoHttp<T>(url: string, init?: RequestInit): Promise<T> {
  const method = (init?.method ?? 'GET').toUpperCase()
  const [path, qs] = url.split('?')

  for (const [m, pattern, handler] of routes) {
    if (m !== method) continue
    const params = match(pattern, path)
    if (!params) continue

    await delay(120 + Math.random() * 180)   // см. §3.5

    const result = await handler({
      params,
      query: new URLSearchParams(qs ?? ''),
      body: init?.body ? JSON.parse(init.body as string) : undefined,
      headers: (init?.headers ?? {}) as Record<string, string>
    })
    return result as T
  }

  throw new ApiError({ message: `Демо: ручка ${method} ${path} не реализована` })
}
```

`match` — простое сопоставление по сегментам: `:name` забирает сегмент в параметры. Регулярку писать не нужно, достаточно `split('/')`.

### 3.4 Состояние

```ts
// src/api/demo/store.ts
import { reactive } from 'vue'
import { buildSeed } from './seed'

export const db = reactive(buildSeed())

export function resetDemo() {
  Object.assign(db, buildSeed())
}
```

`reactive` — чтобы изменения сразу отражались там, где компоненты держат ссылки на объекты.

**Никакого `localStorage`.** Демо должно возвращаться в исходное состояние при перезагрузке — это и есть его механизм защиты от замусоривания.

### 3.5 Искусственная задержка

120–300 мс на запрос. Без неё интерфейс работает подозрительно мгновенно, скелетоны загрузки не успевают показаться, и демо перестаёт отражать реальное поведение. Для `POST` и `PATCH` можно чуть больше — 200–400 мс.

## 4. Демо-данные

### 4.1 Главное правило: даты считаются от сегодня

Это специфично для ANotes и критично. Дорожная карта, вехи и состояния `AT_RISK` / `OVERDUE` / `LATE` вычисляются относительно текущей даты. Зафиксированный сид через три месяца покажет сплошную просрочку — худшая витрина из возможных.

Все даты задаются **сдвигом**:

```ts
// src/api/demo/seed.ts
const DAY = 86_400_000
const now = Date.now()
const d = (offsetDays: number) => now + offsetDays * DAY
```

### 4.2 Состав

Проект **«Веб-клиент»** — основной, открывается по умолчанию.
Проект **«Обмен данными»** — второй, чтобы работал переключатель и фильтры.

**Статусы первого проекта** (в порядке `statusOrder`):

| Название | `isDefault` | `isClosed` | Цвет |
|---|---|---|---|
| Бэклог | — | — | серый |
| К работе | ✓ | — | серый |
| В работе | — | — | зелёный |
| На ревью | — | — | янтарный |
| Готово | — | ✓ | зелёный |
| Отменена | — | ✓ | серый |

Во втором проекте сделать **другой** набор из трёх статусов — это показывает, что статусы настраиваются, а не зашиты.

**Пользователи:** 4 человека с разными аватарами. Текущий — второй по списку, чтобы фильтр «мои» возвращал непустой результат.

**Эпики первого проекта:** 4 штуки с разной картиной на дорожной карте.

| Эпик | Начало | Конец | Задач | Готово | Состояние |
|---|---|---|---|---|---|
| Переработка обмена | `d(-25)` | `d(+10)` | 5 | 3 | `IN_PROGRESS` |
| Клиент на Vue | `d(-40)` | `d(+3)` | 8 | 2 | `AT_RISK` |
| Уведомления | `d(+5)` | `d(+35)` | 5 | 0 | `NOT_STARTED` |
| База знаний | `d(-60)` | `d(-5)` | 4 | 4 | `DONE` |

Плюс **один эпик без дат** — он должен попасть в блок «Без сроков» под шкалой. Это проверяет ветку, которую легко не заметить.

**Задачи:** 25–30 штук. Обязательно среди них:

- 2–3 просроченные (`dueDate = d(-3)`, статус не закрывающий) — красят индикаторы;
- 3–4 без эпика — наполняют группу «Без эпика»;
- 1 задача с 6 комментариями, из них 2 с `actorType: 'AGENT'` — главная витрина продукта;
- 1 задача с заполненным `summary` — показывает результат работы агента;
- 4–5 записей учёта времени, чтобы отчёты не были пустыми;
- задачи, распределённые по всем статусам — иначе доска покажет пустые колонки.

**Вехи:** три с разными состояниями.

| Веха | Срок | Задач | Готово | Состояние |
|---|---|---|---|---|
| Релиз 1.2 | `d(+12)` | 12 | 8 | `IN_PROGRESS` |
| Демо заказчику | `d(+34)` | 9 | 2 | `PLANNED` |
| Релиз 1.1 | `d(-8)` | 6 | 6 | `READY` |

`READY` важна отдельно: она показывает баннер «Все задачи выполнены. Закрыть веху?» — то самое поведение «предлагать, а не решать».

**Вики:** 5 страниц, из них 2 вложенные (второй уровень). В одной — ссылка `[[Формат манифеста]]` на существующую страницу, ссылка `[[Несуществующая]]` (красная) и ссылка `#42` на задачу. У одной страницы 3 ревизии, чтобы работала история с диффом.

**Уведомления:** 3 непрочитанных разных типов — чтобы колокольчик показывал счётчик.

### 4.3 Тексты

Осмысленные, на русском, из области разработки ПО. «Задача 1», «Тест», «asdf» обесценивают демонстрацию: посетитель смотрит на него как на витрину продукта, а не как на тестовые данные.

## 5. Что заглушить особым образом

### 5.1 Вход

Форма входа остаётся, но принимает **любые** логин и пароль. Над полями — подсказка:

```
Демо-режим: войдите с любыми данными.
Изменения хранятся только в этой вкладке и пропадут при перезагрузке.
```

`login` возвращает фиктивный токен и пользователя. Проверок нет.

### 5.2 Оптимистичная блокировка

`PATCH` увеличивает `version` и **никогда не возвращает `409`** — конфликтовать не с кем.

Но одну задачу можно пометить как «конфликтную»: при попытке её сохранить вернуть `409` один раз, чтобы показать диалог разрешения. Делать это только если человек попросит — по умолчанию не стоит, посетитель воспримет как поломку.

### 5.3 Файлы

Загрузка отключается. Кнопка остаётся, при нажатии — тост «В демо загрузка файлов недоступна». В списке файлов — 2–3 фиктивные записи с именами и размерами, скачивание не работает.

### 5.4 Агент

`POST /auth/agent-token` возвращает правдоподобный, но нерабочий токен. На странице `/agent` — баннер:

```
Это демо без сервера. Токен сгенерирован локально и никуда не подойдёт.
Чтобы попробовать агента по-настоящему, разверните ANotes у себя.
```

Всё остальное на странице — адреса, системный промпт, «может / не может», блок «Всё одним куском» — показывается как есть. Это витрина главной функции, скрывать её нельзя.

### 5.5 Уведомления

Опрос `GET /notifications/count` работает, но счётчик не меняется сам. Отметка «прочитано» уменьшает число в памяти.

### 5.6 Администрирование

`GET /api/admin/users` возвращает `403` — демо-пользователь не администратор. Экран `/people` покажет каталог только для чтения, как и задумано в боевом приложении.

## 7. Деплой

### 7.1 Workflow

```yaml
# .github/workflows/demo.yml
name: Deploy demo to Pages

on:
  push:
    branches: [main]
  workflow_dispatch:

permissions:
  contents: read
  pages: write
  id-token: write

concurrency:
  group: pages
  cancel-in-progress: true

jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: npm
      - run: npm ci
      - run: npm run build:demo
      - uses: actions/configure-pages@v5
      - uses: actions/upload-pages-artifact@v3
        with:
          path: dist

  deploy:
    needs: build
    runs-on: ubuntu-latest
    environment:
      name: github-pages
      url: ${{ steps.deployment.outputs.page_url }}
    steps:
      - id: deployment
        uses: actions/deploy-pages@v4
```

Версия Node — 22, в соответствии с `engines` (`^20.19.0 || >=22.12.0`).

### 7.2 Настройка репозитория

**Settings → Pages → Source: GitHub Actions.** Не «Deploy from a branch» — иначе workflow отработает, а сайт не обновится.

### 7.3 Проверка перед объявлением

Обязательно **на задеплоенном сайте**, не локально:

- [ ] корневой адрес открывается, стили и шрифты загрузились;
- [ ] в консоли нет 404 на ассеты (признак неверного `base`);
- [ ] вход проходит с произвольными данными;
- [ ] прямая ссылка на задачу работает после `F5`;
- [ ] все четыре режима списка переключаются;
- [ ] карточка перетаскивается на доске;
- [ ] дорожная карта рисует полосы, блок «Без сроков» не пуст;
- [ ] веха «Релиз 1.1» показывает баннер `READY`;
- [ ] в вики открывается страница, история показывает дифф, красная ссылка красная;
- [ ] на задаче с агентскими комментариями видны бейджи «через агента»;
- [ ] переключатель «Скрыть действия агента» работает;
- [ ] `/agent` показывает баннер про нерабочий токен;
- [ ] ни одного необработанного «ручка не реализована» в консоли при обходе всех экранов.

Последний пункт проверяется обходом каждого экрана с открытой консолью.

## 10. Признаки того, что что-то пошло не так

Самопроверка:

- Вы правите файлы вне `src/api/demo/` и `http.ts` — кроме роутера, `vite.config.ts` и `App.vue` менять ничего не требуется.
- В компонентах появились проверки `if (isDemo)` — вся разница должна жить в транспорте.
- Демо использует `localStorage` для доменных данных — тогда оно перестаёт сбрасываться.
- Сид содержит абсолютные даты вместо сдвигов — через месяц демо станет красным.
- Боевая сборка `npm run build` перестала проходить — демо не должно её задевать.

Если хоть один пункт про вас — остановитесь и сообщите человеку до того, как продолжать.
